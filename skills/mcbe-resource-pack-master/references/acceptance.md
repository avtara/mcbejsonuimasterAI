# Acceptance by requested artifact

1. Preserve the user's chosen surface. A requested attachable UI is not satisfied by a generic form, and a native inventory is not satisfied by an ActionForm callback.
2. Inspect the whole requested component's source graph. Count unresolved references and unsupported expressions; do not hide them behind a summary `ok`.
3. For reusable skill/tool changes, run meaningful negative cases and a fresh task using only the selected skill and minimum raw files. Test whether it chooses the right owner and refuses unsupported claims; exact wording is not the acceptance criterion.
4. For visuals, compare the full composition and interaction states at the intended camera, GUI scale, viewport and graphics mode. Match texture density, palette roles, silhouette, text space and focus visibility; preview evidence must name what it cannot simulate.
5. For game implementations, verify input/state updates in Bedrock and inspect a fresh Content Log. Test the requested first/third person, multiplayer and equipment lifecycle branches. Rendering one still image does not establish these branches.

Return artifacts, changed behavior, checked evidence and unresolved requirements. Prefer one selected research card or exact graph issue over a full source dump. Preserve file/commit hashes in local provenance so a later failure can be traced without rereading every source.
